# 图灵实验室 v1.7 使用指南

本文是当前版本的主要使用入口。旧版本升级记录保留在仓库的 `UPGRADE_*.md` 文件中；其中的旧界面步骤不应代替本指南。

## 1. 账号注册与登录

1. 打开网站，选择“注册账号”，填写用户名和密码。注册不需要邀请码；用户名允许重名，长度为 1～40 个字符，密码至少 8 位。
2. 注册成功后，平台自动分配唯一 UID，例如 `TL00000001`。在大厅复制并保存 UID。
3. 日常使用 UID 和密码登录。升级前创建的旧账号如果暂时不知道 UID，可在登录页选择“使用旧登录名”登录，进入大厅后查看自己的 UID。
4. UID 由账号主键生成，已分配的 UID 永不重用。删除账号不会把旧 UID 分配给新账号。

**用户名不是登录时的唯一身份标识；请保存 UID，不要只记用户名。**

## 2. 创建房间与加入身份

### 创建房间

- 登录后进入比赛大厅，使用“创建一场图灵测试”填写比赛名称并创建房间。
- 创建者成为该房间的房主，可以管理本房间的参赛者、裁判、AI 席位、模型配置、轮次和比赛揭晓。
- 房主可复制房间邀请码，发给需要加入的玩家或裁判。全站管理员可以管理所有房间。

### 以参赛者身份加入

1. 先注册账号并使用 UID 登录。
2. 在大厅“加入已有房间”区域输入房主提供的邀请码。
3. “加入身份”选择“参赛者”，点击“加入比赛”。

### 以真人裁判身份加入

1. 真人裁判自行注册账号，不需要房主代建账号。
2. 使用自己的 UID 和密码登录。
3. 在大厅输入目标房间的邀请码。
4. 在“加入身份”中选择 **“真人裁判”**，然后加入比赛。

真人裁判限制：

- 同一个账号同一时间只能担任一个**未完赛房间**的真人裁判。若账号已在其他未完赛房间担任裁判，必须先完成那场比赛，才能加入另一场。
- 房主不能同时担任自己房间的独立真人裁判；本房间参赛者也不能同时担任本房间裁判。
- 全站管理员账号不能作为独立真人裁判加入。
- 已完赛房间会保留裁判名单。若该房间再次开赛时，某位保留裁判仍在其他未完赛房间担任裁判，系统会阻止再次开赛；先完成其他房间的比赛，再重新开赛。

## 3. 比赛流程

### 真人裁判出题与统一作答

1. 真人裁判使用自己的账号进入房间，在独立裁判界面提交本轮问题。
2. 房主在裁判管理页查看问题，确认问题已准备好后点击 **“开始统一作答”**。
3. 对于已绑定模型 API 的 AI 裁判，浏览器会先触发缺失问题生成，再开启本轮，随后触发模型 AI 参赛者回答生成。
4. 所有参赛者（包括 AI）提交回答后，服务器会统一公开本轮回答。
5. 全部轮次完成后，各真人裁判分别提交自己的最终判断。裁判之间不能查看彼此尚未公开的判断。
6. 所有裁判锁定判断后，房主可以揭晓身份与计分。

**自动调用不是服务器独立运行的后台任务。** “开始统一作答”由当前浏览器按顺序发起请求；如果页面、网络或某一步请求中断，后续步骤可能没有触发。

### 手动发布问题与 AI 回答

房主管理台还保留 **“向所有玩家发布问题”** 的手动入口。它用于房主录入外部裁判的问题并发布给玩家，**不会自动生成模型 AI 参赛者的回答**。

使用这条路径时：

- 对绑定模型 API、但尚未回答的 AI 参赛者，房主需要另外点击 **“自动生成模型 AI 回复”**。
- 未绑定模型 API 的 AI 参赛者，需要房主通过“录入 AI 回答”表单粘贴原始回答。
- 如果模型 AI 回答生成失败或中断，只要该席位仍未提交且本轮仍在收集回答，房主管理台就会显示补触发按钮，可再次点击。

模型 AI 裁判的问题也有单独的 **“让模型自动生成本轮问题”** 入口；模型 AI 裁判的最终判断则由房主在全部轮次完成后单独触发。

## 4. AI 模型 API

模型 API 使用 OpenAI Chat Completions 兼容协议。房主在房间的“模型 API 接入”页面创建配置，再将配置分配给 AI 参赛者或 AI 裁判。

常用配置字段：

| 字段 | 说明 |
|---|---|
| 配置名称 | 便于区分服务商或用途 |
| Base URL | OpenAI 兼容 API 根地址，例如 `https://api.openai.com/v1`；不要附加 `/chat/completions` |
| 模型名称 | 服务商提供的模型 ID |
| API Key | 对应服务商的密钥 |
| Temperature | 0～2 |
| 最大输出 Token | 64～8192 |
| 请求超时 | 10～120 秒 |

- 选择模型配置的 AI 席位可以使用自动出题、回答或最终判断功能；选择“手动转录”的席位继续使用手动录入。
- 当前模型 API 仅允许 HTTPS 公网地址。模型服务商的 API 用量可能单独计费。
- API Key 使用 Fernet 加密后存入 SQLite。Railway 服务端必须配置长期固定的 `MODEL_CREDENTIAL_KEY`；生成、保存和恢复方式见 [Railway 部署说明](RAILWAY_部署说明.md)。
- **不要更换或丢失 `MODEL_CREDENTIAL_KEY`。** Railway 启动时会检查密钥格式，并逐条验证数据库中已保存的 API Key 能否解密；密钥缺失、格式错误或与现存数据不匹配时，服务会拒绝启动。修复变量后再重新部署；也不要把密钥或 API Key 提交到 GitHub。

## 5. 房间复用、记录与 UID

- 比赛完成后，房主可以使用“再次开赛”复用房间。房间、邀请码和保留名单继续使用，上一场的比赛问题、回答、裁判判断、日志和快照会被清空。
- 再次开赛前，系统会检查保留的真人裁判是否仍在其他未完赛房间任职；存在冲突时会拒绝开赛，不会先清空上一场记录。
- 比赛结束后可下载整场 Log。需要保留历史记录时，请先下载并妥善保存。
- 删除房间会永久删除该房间及其比赛数据；这与“清空完赛记录后复用房间”不是同一操作。

## 6. 本地测试与 CI

项目的浏览器验收测试包括 `tests/test_uid_ui.py` 和 `tests/test_host_ui.py`，两者都会启动 Playwright 浏览器。

无 Microsoft Edge、也不准备运行浏览器验收时，运行后端测试应同时排除这两个文件：

```powershell
python -m pytest -q --ignore=tests/test_uid_ui.py --ignore=tests/test_host_ui.py
```

本机安装 Playwright Chromium 后，可在 PowerShell 中运行完整测试：

```powershell
npm install --no-save playwright
npx playwright install chromium
$env:PLAYWRIGHT_CHANNEL = "default"
python -m pytest -q
```

GitHub Actions 的 `.github/workflows/tests.yml` 已安装 Chromium，并设置 `PLAYWRIGHT_CHANNEL=default` 后执行完整的 `python -m pytest -q`；CI 不依赖 Microsoft Edge。
