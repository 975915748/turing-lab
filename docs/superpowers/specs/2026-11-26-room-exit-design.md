# 主动退房与关闭房间设计

用户确认：返回大厅算作主动退出；退出或被移除后解除该房间的锁名。房主返回大厅关闭房间，停止比赛保留记录，不当作完赛、不结算积分。房主在参赛者管理可仅退赛，保留房间与管理权限。

本规则替代旧好友／积分需求中的“移除后仍锁名”要求；不会解除其他开放比赛中的有效身份锁。UID、积分计算公式、好友私信及模型配置所有权不变。

采用服务端持久状态，而不是页面变量判断退房：普通玩家软退出并保留历史回答；真人裁判软退出保留历史问题/判决但不再参与本场有效裁判集合；房主退房写入 closed 状态。刷新、断网、进入个人中心不退房。其他房间有效角色仍独立约束改名。

开局前主动退房可按原名单准入条件重新加入；开局后退出禁止重新参赛，下一场可加入；踢出与主动退出区分，踢出不可重入本场。房主仅退赛不关闭房间。

关闭后只读保留原比赛资料和聊天，不结算积分、不清理日志；原参与者可查看所保留的权限内资料。已正式完赛后房主离开不改写完赛状态或积分。关闭房间可由房主/管理员显式重新开赛，必须确认清空旧记录。

安全准入：开局前重入仍须满足人数上限和原名单规则；开局后已退出裁判不能改换玩家身份重入。退出接口须校验登录、CSRF、场次与确认，重复退出幂等。关闭使排队／请求中的模型任务失效；已经发出的服务商请求可能计费，迟到结果不能写回比赛。

替代方案：仅断开 WebSocket 不能维护账号级权限；删除房间会丢失历史，与用户选择冲突；因此均不采用。
