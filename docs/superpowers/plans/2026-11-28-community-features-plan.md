# 好友邀房、公开大厅与出题灵感库实施计划

> 执行依据：docs/superpowers/specs/2026-11-28-community-features-design.md  
> 目标：实现好友一键邀房、公开大厅房间列表和内置出题灵感库。  
> 基线：main 当前代码。  
> 技术栈：FastAPI、SQLite、原生 JavaScript、pytest、Playwright。  
> 本计划只描述后续实施步骤；实施时应在独立功能分支上完成，不直接修改 main，不部署生产环境。

## 全局约束

- 先阅读并遵循设计规格；遇到代码与规格不一致时，先查清现有行为，不得直接绕过权限检查。
- 保留邀请码加入流程、好友关系、私信、账号级 WebSocket、名字锁定、角色互斥和比赛工作流。
- 共享加入逻辑必须复用现有参赛者 / 真人裁判准入函数。
- 旧房间默认私密；新增字段迁移不得重建或清空 SQLite 数据。
- 公开列表不得返回邀请码、UID、私聊、题目答案、裁判判断或模型凭据。
- 题库只读；不恢复已停用的 suggestions API。
- 不实现赛后战报、观战席、积分榜、桌面通知、用户投稿或题库收藏。
- 异步前端响应必须校验 UID、CSRF、账号 epoch 和当前 socket，防止账号切换串号。
- 不改生产数据、密钥、Railway 配置或部署状态。

- [ ] 统一处理房间状态、参赛者加入、真人裁判加入、已有成员幂等返回、退赛重入规则。
- [ ] 继续调用 ensure_roster_unlocked、active_participant_count、check_judge_registration 等现有校验。

- [ ] 新增或补充后端测试，覆盖原邀请码加入的 player / judge、重复加入、满员、锁名、角色互斥、裁判跨房间冲突和房间关闭。
- [ ] 确认该阶段不改变任何既有加入行为。

## 阶段 2：好友一键邀房

### 数据层与接口

- [ ] 在 social.py 的 ensure_app_schema() 新增 room_invites 表、状态 CHECK、查询索引和 pending 部分唯一索引。
- [ ] 迁移必须幂等，旧好友、私信、积分数据保持不变。
- [ ] 新增 GET /api/me/room-invites，返回当前用户收到和发出的待处理邀请，并惰性更新过期记录。
- [ ] 新增 POST /api/rooms/{room_id}/invites，校验房间管理权限、好友关系、账号状态、请求数量和速率限制。
- [ ] 单次最多 20 个目标；逐个返回成功 / 跳过结果，不能因单个无效目标丢失其他成功邀请。
- [ ] 新增 accept、reject、cancel 接口，所有写操作执行 Origin、CSRF 和当前用户权限检查。
- [ ] accept 使用 immediate transaction：重读邀请、检查有效期和好友关系、调用共享加入函数、更新邀请状态。
- [ ] accept 对已成功加入的重复请求幂等；失败时不留下半完成的成员记录。
- [ ] 在房间开赛和关闭的状态转换中取消待处理邀请；好友删除、账号软删除时取消相关邀请。
- [ ] 到期邀请在列表读取或接受时更新为 expired，不增加后台定时任务。

### WebSocket 与前端

- [ ] 扩展 /ws/messages 的事件类型，增加 room_invite_created 和 room_invite_updated。
- [ ] 调整账号 socket 生命周期，使已登录用户在大厅和房间中也能收到邀请事件；避免仅在个人中心连接。
- [ ] socket 建立、重连、消息处理和异步刷新均核对 UID、CSRF、账号 epoch、socket 实例。
- [ ] 大厅增加待处理邀请角标和邀请列表，展示房间名、邀请人、受邀身份和剩余有效期。
- [ ] 房间管理视图在名单可变更时增加“邀请好友”按钮。
- [ ] 好友选择面板支持多选和本批统一身份；无好友时提供前往个人中心的入口。
- [ ] 接收者可接受 / 拒绝；发送者可撤回；接受成功后直接打开房间。
- [ ] 当前处于房间时收到邀请，显示轻量通知和“去大厅查看”入口，不强制切换当前比赛。
- [ ] 退出登录、切换账号和 socket 断开时清理邀请状态与旧请求。

### 测试

- [ ] 新增 tests/test_room_invites.py，覆盖好友校验、权限、重复邀请、批量部分失败、状态流转、到期、好友删除、账号删除、开赛 / 关房失效。
- [ ] 覆盖接受邀请的玩家 / 裁判两种角色，以及所有既有角色约束。
- [ ] 覆盖并发接受、双击接受、接受与开赛竞争、接受与满员竞争。
- [ ] 覆盖账号 WebSocket 通知、未登录拒绝、旧账号事件迟到和账号切换。
- [ ] 保留并运行现有 tests/test_social_points.py 与好友私信浏览器回归。

## 阶段 3：公开大厅房间列表

### 数据层与 API

- [ ] 在 rooms 表增加 public_listing INTEGER NOT NULL DEFAULT 0。
- [ ] 增加 public_description TEXT NOT NULL DEFAULT ''。
- [ ] 在 app.py 的 init_db() 中实现兼容旧库的增量迁移；确认旧房间全部保持私密。
- [ ] 扩展 RoomData，新增可选 public_listing 和 public_description；旧客户端不传时默认私密。
- [ ] 新增 PUT /api/rooms/{room_id}/visibility，仅房主 / 管理员可在首轮开赛前修改。
- [ ] 新增 GET /api/public/rooms，支持 limit、before_id，最多返回 50 条。
- [ ] 公开列表只返回仍可加入的房间，并按当前浏览者计算 can_join_player / can_join_judge。
- [ ] 公开列表只返回概览字段和由配置计算的 tags；不得返回邀请码或房间内部数据。
- [ ] 新增 POST /api/rooms/{room_id}/join，仅允许当前公开且仍可加入的房间，调用阶段 1 的共享加入函数。
- [ ] 开赛后自动从列表移除；再次开赛后按保留的 public_listing 状态重新判断。

### 前端

- [ ] 创建房间表单增加默认关闭的“公开在大厅展示”开关和 160 字说明。
- [ ] 大厅增加“公开对局”区域、刷新按钮和分页加载。
- [ ] 房间卡片显示房名、房主昵称、参赛人数、裁判数量、限时、自动标签和说明。
- [ ] 按 can_join_player / can_join_judge 显示身份加入入口。
- [ ] 房间管理视图在首轮开赛前增加公开状态和说明编辑。
- [ ] 开赛后停止公开展示，并隐藏修改入口。
- [ ] 保留邀请码输入框和原有我的房间列表，不改变旧加入路径。

### 测试

- [ ] 新增 tests/test_public_rooms.py。
- [ ] 覆盖新建默认私密、旧库迁移默认私密、房主 / 管理员修改权限、开赛后禁止修改。
- [ ] 覆盖私密、已开赛、已完赛、已关闭、名单锁定房间不会出现在公开列表。
- [ ] 覆盖 player / judge 两种加入路径及满员、角色冲突、跨房间裁判冲突。
- [ ] 覆盖分页、字段白名单和邀请码 / UID / 模型凭据不泄露。
- [ ] 覆盖再次开赛后公开状态保留且仅在重新满足条件时出现。

## 阶段 4：内置出题灵感库

### 数据与接口

- [ ] 新增 question_bank.py，集中保存版本号、分类和至少 24 条内置题目。
- [ ] 分类至少包括逻辑陷阱、中文语境与表达、主观体验与记忆、多轮追问，每类不少于 6 条。
- [ ] 每条题目使用稳定 ID，包含 category、title、text、tags。
- [ ] 题目正文长度不超过真人裁判问题接口的 3000 字限制。
- [ ] 新增只读 GET /api/question-bank，支持 category、q、limit。
- [ ] 接口要求登录；不新增写入 API 和数据库表。
- [ ] 不复用已返回 410 的 /api/rooms/{room_id}/suggestions。

### 前端

- [ ] 只在真人独立裁判可提交的 judge-question 表单旁增加“出题灵感”入口。
- [ ] 增加分类筛选、关键词搜索、随机抽取和题目预览。
- [ ] “填入”只更新当前 textarea，不自动调用提交 API。
- [ ] 非空草稿替换前二次确认；取消后保留原文。
- [ ] 题库面板开关和筛选不得清空用户草稿。
- [ ] 使用 esc() 等现有安全方式渲染题库标题、标签和正文。
- [ ] 不接入 AI 裁判原文代录和外部裁判原文转录表单。

### 测试

- [ ] 新增 tests/test_question_bank.py，覆盖分类、搜索、随机结果、稳定 ID、登录权限和只读行为。
- [ ] 覆盖题目长度和响应字段白名单。
- [ ] 浏览器测试覆盖分类切换、搜索、随机抽题、填入后编辑、非空草稿确认和取消保留。
- [ ] 确认点击填入不会提交问题；最终仍由原有提交按钮和 API 完成提交。
- [ ] 确认 AI 裁判代录表单和外部裁判转录表单没有题库入口。

## 最终审查重点

1. 是否存在任何绕过 /api/join 现有准入规则的新路径。
2. 邀请接受与开赛、关房、满员、角色冲突并发时是否保持事务一致。
3. 是否因账号 socket 全局化而引入旧账号事件覆盖新账号状态的问题。
4. 公开列表是否通过字段白名单严格避免泄露邀请码、UID、模型配置和比赛内部内容。
5. 公开房间是否只在名单确实可变更时出现，而不是只检查 status='open'。
6. 题库内容是否只作为可编辑草稿，不会自动提交或混入 AI / 外部裁判原文转录。
7. 新增迁移是否可重复执行，且不会改变旧房间默认私密状态。
