## 阅读顺序

1. 先读项目总览，弄清楚角色、模块和数据流。
2. 按负责范围阅读前端或后端指南。
3. 修改接口前查阅 API 约定，同时核对 app.py 中的实际实现。
4. 修改比赛规则或权限前阅读比赛规则，并补充对应回归测试。
5. 按贡献流程创建分支、运行测试并提交 PR。

## 文档约定

- **代码是最终事实来源**。文档用于解释代码，不覆盖代码。
- 文档中的“当前实现”表示已在基线提交中核对；“建议”表示协作约定，不代表仓库已经强制执行。
- 不确定的行为应标记待核对，不应根据 UI 文案或旧版本升级说明推断后端行为。
- 不要把生产数据库、API Key、管理员密码、Cookie、服务器 Token 或环境变量密钥提交到仓库。
